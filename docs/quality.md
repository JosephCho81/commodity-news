news.a1kor.com 리포트(시장 5개 + 브리핑)가 지켜야 할 기준. **측정할 수 있는 것만** 넣는다.
결함은 `api/_lib/quality.js`가 매일 세고(`report.quality`), `/api/audit`로 본다. 기준을 바꾸면 이 문서·코드·테스트를 같이 바꾼다.

## 생성 단계 검증 → 게시 게이트
1. **해석 입력**(interpret.js): 원/달러 방향 줄(코드 계산), 시세마다 휴장 표시, 14일 넘은 고시·야드 시세 표시, 관세청 단가는 기준월을 밝히라는 표시, 기사마다 나이·이전 보도·실적 기사 표시, 기사 문장 번호. 원화 환산 줄의 환율 효과(시세 거래일 기준)가 방향 줄과 반대 부호면 넘기지 않는다(2026-10-19 "환율 상승 효과" 4건의 원인).
2. **인용 대조**(G2, `cite.js`): now·원인마다 근거 문장 번호("기사-문장", 헤드라인은 "0-k")를 단다. 없는 번호, 인용 문장·코드 숫자 줄에 없는 숫자, 근거도 코드 숫자도 없는 서술은 버린다(`dropped`에 `G2`). 원인의 `src`는 인용한 기사 번호로 바로잡는다.
3. **게시 게이트**(`gate.js`): 위 표의 H 판정 문장을 지운다. 문단 칸(브리핑 첫 문단·전망·상방·하방)은 그 문장만, 짧은 항목(지금·원인·영향·변수·공통 요인)은 통째로. 제목·한 줄 요약은 코드 방향 판정("가탄제 약세")으로 대체 — 지어내지 않는다. 공통 요인은 제목 중복·20자 미만을 뺀다.
4. **LLM 검수**(C3, `judge.js`): 게이트 저장 뒤 함수 남은 시간이 45초 이상이면 1회(60초 상한). 코드 사실(방향·시세 날짜·휴장·원/달러 방향·고시 기준일)과 문장별 근거 기사 날짜를 주고 모순·지난 일 현재형·근거 없음 문장 번호만 받는다(최대 5문장 — 코드 숫자를 주지 않았던 첫 시험 실행에서 맞는 문장 8개를 골랐다). 고른 문장을 게이트가 지우고 다시 저장. 실패하면 3의 저장본 유지.

## 세계 동향 검증 (2026-11-17~, `exploreVerify.js`)
사안은 "사실"과 "추론"을 칸으로 나누고 다른 규칙을 건다. 화면에 "AI 분석" 표시는 붙이지 않는다(사용자 결정) — 문장 형태로 구분된다. 리포트의 검증 규칙은 하나도 풀지 않았다(같은 함수를 그대로 쓴다).
1. **출처**: LLM이 찾은 주소를 코드가 직접 연다(`evidence.getText`, GBK 해독 같음). 인용문이 원문에 그대로 있어야 하고(20자 이상, 공백·따옴표 모양만 무시), 발행일은 페이지 메타 → LLM이 말한 날짜가 본문에 적혀 있을 때(영어·중국어·한국어 날짜) → 검색 색인 날짜 순으로만 인정, 최근 14일. 정부·국제기구·통신사(로이터·AP·블룸버그·연합·신화 등)·근거 매체(`evidence.js DOMAINS`)가 아니면 다른 사이트 1곳이 같은 검증을 통과해야 한다. 시장 규모 홍보 글·보도자료 배포 사이트·SNS·영상·PDF 제외.
2. **사실 문장**(`what`): 근거 문장 번호 필수(`cite.js citeCheck`, 그 사안의 기사 인용), 숫자(`numbersOk`)·통화 단위(`unitsOk`)가 입력·인용 문장에 있어야 한다. 이 칸에만 더한 조임:
   - 만·억·천 단위 수는 풀어 쓴 값이 인용 문장에 있어야 한다("1만1000"을 1과 1000으로 따로 보던 빈틈). 원문이 万·亿·만·억으로 쓴 수는 풀어서 비교하고, **영어 million·billion을 만·억으로 바꾼 수는 환산이라 탈락**(45 million → 4,500만). 그래서 영어 기사 숫자는 "45백만 톤"·"2.5십억 달러"로 쓴다 — "백만·십억" 앞의 1~2자리 수도 같은 규모어(million·Mt·百万)와 함께 인용 문장에 있어야 한다.
   - 단위가 붙은 1~2자리 수(30%, 톤당 80달러)도 인용 문장에 있어야 한다 — 기존 대조는 1~2자리 수를 날짜·개수로 보고 넘겨 30%를 40%로 바꿔도 통과했다(리포트 해설에는 아직 남은 빈틈, 아래 한계).
   - "US$·$·USD"는 값을 바꾸지 않고 "달러"로 통일(S2).
   사실 문장이 0이면 사안을 내지 않는다.
3. **추론 문장**(`relation` 품목과의 관계·`reach` 영향 범위·`outlook` 앞으로 예상): 숫자 금지(기간 표현만), 영향 범위·예상은 추정 표현("~로 보인다", "~할 전망이다", "~할 수 있다")일 때만. 품목과의 관계는 LLM의 일반 지식이라 출처 대조가 없다 — **코드가 보장하지 못하는 칸**. 추론 문장이 0이면 사안을 내지 않는다. 칸 이름을 `link`로 지으면 모델이 주소를 넣는다(glove-news) — 출력 칸 이름은 다른 뜻으로 읽히지 않게.
4. 공통: 위안 표기(`noCny`)·게시 게이트 H(`quality.sentenceIssues` — F1·F2·C1, 직전 리포트의 원/달러 방향·고시 기준일로)는 리포트와 같은 함수. 구매 지시·모른다는 문장·지난 날짜 예고는 이 프로젝트 리포트에 코드 판정이 없어(프롬프트만) `exploreVerify.js`에 새로 두었다.
5. 규모(`scale`)·방향(`effect`)·품목(`markets`)은 LLM 판단이다. 코드가 검증하지 않는다 — 정렬·품목 탭 분류에만 쓴다.
6. 격리: 낯선 페이지·출력 하나가 던져도 그 사안만 탈락(깨진 숫자 엔티티 `&#2013266080;`는 `decodeEntities`가 그대로 둔다 — 근거 기사 수집도 같은 함수). 사안이 없거나 작성이 실패하면 직전 사안(14일 이내)을 발표일과 함께 유지, 처음 다룬 날부터 3일은 새 사안 뒤에 이어 둔다.
7. 첫 주소가 자동 접속을 막으면(로이터 등) 두 번째 매체를 주 근거로 본다 — 같은 원문 대조를 통과하고 공식·통신사·근거 매체일 때만. 영어 무게 단위는 값을 바꾸지 않고 한국어로(mt → 톤, Mt → 백만 톤). 추론 문장의 "1차·2차 알루미늄"은 품목 이름이라 숫자로 보지 않는다.
8. 감사: `/api/audit?date=`가 그날 `world_{날짜}` 문장도 같은 기준(F1·F2·C1·S2)으로 센다(`reportTexts`에 포함).

신호 소스 실측(2026-11-17, 이 PC에서 직접 요청): 되는 것 — 세계철강협회 RSS·보도자료, FRED CSV(키 없음, 브라우저 UA로는 20초 넘게 걸린 적이 있어 기본 UA), westmetall LME 재고, 상하이항운거래소 SCFI·CBCFI, 미국 연방관보 API, 무역대표부 RSS(`ustr.gov/rss.xml`). 불안정 — Eurostat(이 PC 연결 15초로 Node 기본 연결 제한 10초를 넘겨 실패한 적 있음, curl은 성공), 세계철강협회(한 번 연결 실패). 안 되는 것 — 중국 국가통계국(403), LME 공식 사이트(Cloudflare 403), 상해선물거래소 주간 재고 파일(404), UN Comtrade 중국 페로실리콘 월간(2026-06~09 0건), 관세청 합금철 수입(키가 로컬에 없어 미확인), IAI 알루미늄 생산 통계(연결 실패), AISI 주간 조강(RSS에 없음).

## 운영 한도
- 함수 300초: 검수는 `290초 − 경과`가 45초 이상일 때만, 호출 시간 상한은 `min(60초, 남은 시간 − 20초)`. 평소 수집 전체 약 70초.
- LLM 호출: 하루 6~11회 + 검수 1회 + 세계 동향 6회(탐색 5 + 작성 1). `PPLX_DAILY_CALL_CAP`(기본 40) 안. 모두 `reserveCall`을 지난다.
- 세계 동향 함수 300초: 관점 3개 동시(80초 상한) × 2회 + 원문 받기 + 작성(75초 상한), 작성 전 남은 시간 30초 미만이면 작성 건너뜀.
- Firestore: 리포트 저장이 하루 2회(검수 전·후, 문서 2개씩). `/api/audit?days=N`은 리포트 N건(+품질 장치 이전 리포트는 스냅샷 N건)과 시계열 1건만 읽는다(N ≤ 14).

## 남은 한계(코드로 보장하지 못하는 것)
- 원 기사 자체의 오류, 기사 수집이 놓친 최신 소식.
- 회사 발표를 인용한 문장도 원/달러 방향과 반대면 C1로 지운다(2026-10-24 "환율 상승에 따른 제조원가 부담" — 회사 주장이지만 화면의 환율 서술과 모순).
- 화면의 원화 환산 박스(`metrics.krw.fx_pct`)는 시세 거래일 기준이라 원/달러 1주 변동과 부호가 다를 수 있다(해설 입력에서는 위 1로 막았다).
- LLM 검수는 확률적이다 — 모순을 놓치거나 맞는 문장을 고를 수 있다(상한 5문장으로 피해를 제한).
- 리포트 해설의 숫자 대조(`numbersOk`·`citeCheck`)는 1~2자리 수를 보지 않는다(30%→40% 통과). 세계 동향에만 조임을 넣었고, 리포트 생성 코드는 이번 작업 범위 밖이라 그대로 두었다.
- 세계 동향의 "품목과의 관계"·규모·방향·품목 분류는 LLM 판단이다(위 세계 동향 3·5). 예측 채점은 아직 없다.
